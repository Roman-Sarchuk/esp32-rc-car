
# ESP32 RC Car (Freenove ESP32 WROVER)

A small embedded + fullstack RC car project built around the Freenove ESP32 WROVER. This repo contains the firmware that runs on the ESP32 (motor control, sensors, web server) and a frontend web app (React + Vite) used as a control UI.

## Hardware

- Chassis / body of the car
- 2 DC motors + wheels
- 1 roller (idler) wheel
- Motor driver (H-bridge)
- Freenove ESP32 WROVER
- HC-SR04 ultrasonic distance sensor
- 2 yellow LEDs (status/indicator)
- 2 red LEDs (status/indicator)
- Battery pack (power)

Note: exact motor driver model and wiring vary by build — check `firmware/src/main.cpp` for pin assignments used in code.

## Features

- Remote control via web UI hosted by the ESP32 or served from the frontend app
- Motor control for forward/reverse and steering (differential drive)
- Obstacle detection using HC-SR04 ultrasonic sensor
- Simple status indicators with onboard LEDs
- Web UI can be served from the ESP32's filesystem (`firmware/data`) or from the separate frontend during development

## Repository layout

- `firmware/` — PlatformIO-based ESP32 firmware. Web UI static files live in `firmware/data/` and are served by the ESP Async Web Server.
- `frontend/` — React + Vite UI project used to develop the control interface. Build artifacts can be copied into `firmware/data/` for the ESP to serve.

## Getting started

Prerequisites

- [PlatformIO](https://platformio.org/) (VS Code PlatformIO extension or `platformio` CLI)
- Node.js + npm (for the frontend)
- USB cable and drivers for your ESP32 board

Firmware: build & upload

1. Build and upload using PlatformIO (recommended via VS Code):

```
cd firmware
platformio run
platformio run --target upload
```

2. Or use the PlatformIO extension in VS Code — open the `firmware` folder and use the Build / Upload buttons.

Frontend: dev & build

1. Run the frontend UI locally for development:

```
cd frontend
npm install
npm run dev
```

2. Build the production UI and copy artifacts to the firmware `data/` folder so the ESP can serve them:

On macOS / Linux:

```
cd frontend
npm run build
cp -r dist/* ../firmware/data/
```

On Windows (PowerShell):

```
cd frontend
npm run build
robocopy .\dist ..\firmware\data /e
```

After copying the built UI into `firmware/data/`, rebuild and upload the firmware so the web UI is available from the ESP.


**Pinout**

The firmware defines the following GPIO assignments (see `firmware/src/main.cpp`):

| Signal | Function |
|---|---|
| `ENA` (GPIO 14) | Left motor PWM enable (speed)
| `IN1` (GPIO 27) | Left motor direction input 1
| `IN2` (GPIO 26) | Left motor direction input 2
| `ENB` (GPIO 32) | Right motor PWM enable (speed)
| `IN3` (GPIO 25) | Right motor direction input 1
| `IN4` (GPIO 33) | Right motor direction input 2
| `TRIG_PIN` (GPIO 13) | HC-SR04 trigger
| `ECHO_PIN` (GPIO 35) | HC-SR04 echo (input)
| `LED_LEFT` (GPIO 18) | Left indicator LED (blinking)
| `LED_RIGHT` (GPIO 19) | Right indicator LED (blinking)
| `LED_STOP` (GPIO 21) | Brake / stopped indicator LED

Use these GPIOs to wire the motor driver inputs, ultrasonic sensor, and LEDs. If you change pins in code, update this table accordingly.

Wiring notes

- Motors: connect to your H-bridge motor driver outputs; driver inputs to the ESP32 GPIOs referenced in `firmware/src/main.cpp`.
- HC-SR04: connect `TRIG` and `ECHO` to two free GPIOs (use a level shifter or safe input for `ECHO` if needed).
- LEDs: connect with appropriate resistors to chosen GPIOs.
- Power: power motors from the battery via the motor driver; power the ESP32 from a regulated 5V/3.3V as appropriate. Ensure common ground between battery, driver, and ESP32.

Safety

- Double-check wiring before applying power.
- Remove propulsive power when adjusting the chassis.
- Use correct wiring for battery to avoid short circuits.

Where to look in the code

- Firmware main logic and pin definitions: `firmware/src/main.cpp`
- Web UI served by ESP: `firmware/data/index.html` (generated by the frontend build)
- Frontend source: `frontend/src/`
